# Apps Script backend setup

This backend is built under `appsscript\`. It is designed to run as a Google Apps Script Web App that writes to one Google Sheet and stores small media files in the deployer's Google Drive.

## What to deploy

- Code bundle: `appsscript\dist\Code.gs` (generated by `node build.js`)
- Manifest: `appsscript\src\appsscript.json`

You can either:

1. **Paste manually in the browser**
   - Go to <https://script.google.com>
   - Create a new Apps Script project
   - Replace the default script file with the contents of `appsscript\dist\Code.gs`
   - Open **Project Settings** → **Show "appsscript.json" manifest file**
   - Replace the manifest with `appsscript\src\appsscript.json`

2. **Use clasp**
   - Install `clasp` locally
   - `clasp login`
   - `clasp create --type standalone --title "lbrx-language-flash-card-backend"`
   - Copy `appsscript\dist\Code.gs` and `appsscript\src\appsscript.json` into the clasp project
   - `clasp push`

## Required Apps Script deployment settings

- **Deploy as**: Web app
- **Execute as**: **Me** (`"executeAs": "USER_DEPLOYING"`)
- **Who has access**: **Anyone**

Why **Execute as Me**: callers are anonymous at the Apps Script hosting layer, so the script must use the **deployer's** Sheet and Drive permissions for every request. `"USER_DEPLOYING"` is the manifest value for that setting.

## Script Properties

Set these in **Project Settings** → **Script properties**:

- `SPREADSHEET_ID` = the Google Sheet ID used as the database
- `GOOGLE_CLIENT_IDS` = one or more Google OAuth client IDs, comma-separated
- `ALLOWED_EMAILS` = optional, comma-separated allowlist of Google account emails
  permitted to sign in. Leave unset/empty to allow any verified Google account
  (anyone who has the deployed web app URL and your OAuth client ID can then sign
  in with their own account; their data stays isolated from yours by user ID, but
  it still consumes your Sheet/Drive/Apps Script quota). Set this if you want to
  restrict the app to yourself or a small trusted group.

Example:

```text
SPREADSHEET_ID=1AbCdEfGhIjKlMnOpQrStUvWxYz1234567890
GOOGLE_CLIENT_IDS=1234567890-abcdefg.apps.googleusercontent.com
ALLOWED_EMAILS=you@gmail.com,friend@gmail.com
```

## Google Sheet layout

The script bootstraps these tabs automatically if they do not exist.

| Column order |
|---|

### `Cards`

| Column order |
|---|
| `userId`, `serverSeq`, `id`, `deckId`, `front`, `back`, `reading`, `example`, `memo`, `tags`, `imageMediaId`, `hlc`, `createdAt`, `deletedAt` |

### `ReviewLogs`

| Column order |
|---|

### `Media`

| Column order |
|---|
| `userId`, `serverSeq`, `id`, `sha256`, `mime`, `size`, `uploaded`, `driveFileId`, `hlc`, `createdAt`, `deletedAt` |

### `Shares`

| Column order |
|---|
| `userId`, `serverSeq`, `id`, `code`, `deckId`, `createdAt`, `revokedAt` |

| Column order |
|---|
| `key`, `value` |

`Meta` stores:

- `nextServerSeq`: the next integer server sequence to assign
- `mediaFolderId`: the Drive folder ID created for uploaded media

`tags` are stored as a JSON string in a single cell.

## Google OAuth client setup

The frontend uses Google Identity Services. Create a **Web application** OAuth 2.0 client in Google Cloud:

1. Open <https://console.cloud.google.com/>
2. Create/select a project
3. Configure the OAuth consent screen if prompted
4. Create **Credentials** → **OAuth client ID**
5. Choose **Web application**
6. Add your GitHub Pages origin to **Authorized JavaScript origins**, for example:
   - `https://<github-user>.github.io`
7. Copy the client ID and add it to `GOOGLE_CLIENT_IDS`

If you use multiple frontend origins or multiple OAuth clients, add every allowed audience to `GOOGLE_CLIENT_IDS` as a comma-separated list.

## Deploy / redeploy

### First deployment

1. Save the script files
2. Click **Deploy** → **New deployment**
3. Select **Web app**
4. Confirm:
   - Execute as: **Me**
   - Who has access: **Anyone**
5. Deploy
6. Copy the `/exec` URL into the frontend config

### Redeploy after changes

1. Rebuild locally:
   ```powershell
   Set-Location .\appsscript
   node build.js
   ```
2. Paste/push the updated `dist\Code.gs`
3. Create a **new deployment version** (or edit the existing Web App deployment to a new version)
4. Keep the same access settings
5. Reuse the resulting `/exec` URL if Google keeps it stable for that deployment; otherwise update the frontend config

## Smoke test before real auth

This verifies routing/envelope behavior before you have a real Google ID token:

```bash
curl -s -X POST "<WEB_APP_EXEC_URL>" ^
  -H "Content-Type: text/plain;charset=utf-8" ^
  -d "{\"action\":\"auth.ping\",\"idToken\":null,\"payload\":{}}"
```

Expected shape:

```json
{"ok":false,"error":{"code":"unauthorized","message":"Missing Google ID token"}}
```

That proves:

- `doPost` is reachable
- JSON parsing works
- request routing works
- error envelopes are returned correctly

## Getting a real Google ID token for manual testing

Two practical options:

1. **Browser console on a page already using Google Identity Services**
   - Sign in through the frontend
   - Inspect the callback payload or any stored ID token the app exposes

2. **Temporary GIS test page**
   - Load Google Identity Services in a local/static test page
   - Initialize it with your web client ID
   - Sign in and print the returned `credential` JWT

The backend validates the token via Google's `tokeninfo` endpoint and then checks:

- `aud` is in `GOOGLE_CLIENT_IDS`
- `iss` is `accounts.google.com` or `https://accounts.google.com`
- `exp` is still in the future
- `email_verified` is true
- if `ALLOWED_EMAILS` is set, `email` (case-insensitive) is in that list

## Transport rules the frontend must obey

- POST with `Content-Type: text/plain;charset=utf-8`
- JSON string body
- No custom headers
- No `Authorization` header
- Follow redirects (normal `fetch()` behavior)

## Practical media limits

This implementation is intentionally conservative so it stays within Apps Script and CacheService limits:

- Allowed MIME types: `image/jpeg`, `image/png`, `image/webp`, `image/gif`
- Max total media size: **2 MiB**
- Max chunk size: **90,000 base64 characters** (roughly **67 KiB raw bytes**)
- Intended use: small flashcard images only

Uploads are cached chunk-by-chunk in `CacheService`, then assembled on the final chunk, SHA-256 checked, and written to a Drive folder owned by the script deployer.

## Notes

- The backend uses the Google Sheet as the database and rewrites whole tabs in-memory for correctness and Apps Script quota efficiency.
- `sync.push`, all `media.*`, and all `share.*` actions run inside a `LockService` critical section before assigning `serverSeq`.
- The token verification path intentionally uses Google's `tokeninfo` endpoint instead of hand-rolled JWT/JWKS verification because Apps Script has no native JWT library and this approach is simpler and more reliable operationally.
